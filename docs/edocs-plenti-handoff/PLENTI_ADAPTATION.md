# edocs / Plenti：必须适配后才能启用

## 最重要的区别

info 模型是“客户直接发邮件”；Plenti 模型是“第三方转介客户”。当前 `extractSender_` 直接以发件人作为 Lead.Email，原样运行会把 Plenti 联系方式当客户信息，并使多个真实客户发生错误匹配。

必须先取得获准使用的样本：新转介、同一转介重发、补充资料、撤销/状态通知、非销售文件通知。样本至少覆盖 HTML/纯文本以及附件存在的情况。不要把真实客户融资资料发送到未经批准的外部解析服务。

## 实施清单

1. **限定入口**：核实真实 Plenti 发件地址和可信域，结合 Google Workspace 的投递认证结果验证来源。显示名称、主题写有 Plenti 或正文声称来自 Plenti 不足以证明可信。不要盲目信任邮件正文或转发内容里的 Authentication-Results。
2. **独立解析路径**：在通用 `ivClassify_` 前识别已验证的 Plenti 转介格式。Plenti 可能使用 no-reply 地址；不能简单去掉全局自动邮件排除规则。当前 `ivTop_` 会在 From/引用边界截断，可能截掉表单资料，需专门解析 Plenti 格式。
3. **客户身份**：从确定的客户字段取姓名、客户邮箱、电话和安装地址。供应商签名、服务电话不能作为客户信息。缺失或多个客户时进入受控审核，不以 Plenti 邮箱兜底创建。
4. **业务去重**：优先用经验证的稳定 referral / application ID 识别同一转介；Gmail ID 只能防止同一封邮件重复执行，不能防止 Plenti 重发成另一封邮件。客户相同但新项目不应一律拒绝；同一转介补充资料更新已有记录。
5. **跨邮箱去重**：info 和 edocs 若写入同一个 Salesforce，同一客户可能通过两个渠道进入。两个 Apps Script 的 Properties、锁和 Gmail ID 不能提供跨项目原子去重，需要共享的可靠关联/去重策略，并测试并发。不要假设邮箱地址本身就是唯一业务需求编号。
6. **映射及来源**：为 Plenti 建立明确 LeadSource / 来源说明（先核实已有 picklist），保留必要的转介编号和渠道归属。当前 `Other` / `Individual / Residential` 只是原流程默认值；不要误用于企业或其他业务。金额、融资状态等未经确认不推断。
7. **业务边界**：只有实际销售转介创建 Lead。放款、文件处理、安装排期、售后、推广均不能因为来自 Plenti 就创建 Lead。解析不确定的潜在转介进入清晰可见的审核路径，不默默丢弃。
8. **已有客户**：准确匹配 Account / CRN，多候选人工确认。当前 Description 中的 Account 链接只是提示，不是 Lead→Account 外键，也不会自动完成转换；必须验证转换时使用已有 Account 的实际操作。
9. **补录规则**：继续保留“不覆盖冲突字段、保留原文、成功回读后打 Updated”的原则。补录不创建待办 Task；Account 上的老客户 Completed Task 是另一逻辑，需明确是否删除。Lead-only 项目应关闭当前 Opportunity 兜底路径。
10. **收信范围**：原 `runIntakeV2` 会扫描起始时间后的全邮箱（排除垃圾箱/回收站），不是 Plenti 专用查询。必须缩小检索并逐封验证；同一会话里的其他来源邮件也要验证。不通过归档、已读状态判断是否已入库。
11. **敏感资料和告警**：仅留存销售必要信息，不无条件保存整份融资申请/身份证明。原 `.eml` 上传会带入所有原始附件，应先确定允许的数据范围。失败日志需脱敏；告警不能只依赖业务标签。
12. **上线隔离**：先沙箱、独立凭据、独立项目及触发器。确认新 Lead 留在指定审核人，现有 Flow 不会立即分配/发送客户邮件；不要仅检查某个 Flow 显示 Active 就认定安全。

## 验收用例

| 场景 | 验收结果 |
|---|---|
| 可信 Plenti 新转介 | 一个 Lead，使用客户邮箱，不是 Plenti 邮箱；留审核人；标签与实际结果一致 |
| 同一邮件运行两次 | 不重复创建、不重复 Description、不重复原文文件 |
| 同一 referral ID 以新邮件重发 | 不再创建第二个 Lead |
| 同一转介补充电话/地址 | 正确补充原 Lead；冲突转审核；成功后 Updated |
| 同一邮箱不同客户/项目，或多个匹配 | 不随意合并；按明确业务规则审核 |
| info 与 edocs 同时收到同一客户转介 | 不产生竞态重复记录 |
| 冒充 Plenti、推广、售后、文件状态通知 | 不创建 Lead |
| API 写入成功、随后标签失败 | 恢复时只补标签，不重复正文或记录 |
| API 超时且结果不确定 | 先查目标及稳定转介 ID，不盲目再次创建 |
| 解析缺字段、超长正文、敏感附件 | 明确异常处理、可见审核，不丢失或泄露资料 |
| 原 Lead 已转换 | 按 Lead-only 边界处理，不能无意写入 Opportunity |
| 新触发器实际执行身份 | 只操作 edocs 实际收信用户，不是 info 或个人邮箱 |

全部通过后再手动打开安全开关；本包没有完成上述 Plenti 适配。
